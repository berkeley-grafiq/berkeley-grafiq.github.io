Abstract

Vision–language models (VLMs) are increasingly used as judges for image generation and visual reasoning, yet it remains unclear whether they actually understand image formation: the geometry, materials, lighting, and viewpoint that determine appearance. We introduce GRAFIQ (Graphic Intelligence Quotient), a synthetic benchmark that isolates these factors through deterministic Blender renders and viewer–relative forced–choice questions. Each item's ground truth is verified directly against render passes (depth, glossy–direct, surface–normal, or diffuse–direct), so the correct answer is supported by the image evidence rather than only by the scene graph.

We evaluate seven VLMs on a 480–item recognition split (four tasks × 120 items): two open local models (Qwen2.5–VL–7B–Instruct, Qwen3–VL–8B–Thinking) and five API models (GLM–4.5V, GPT–4o–mini, GPT–5–mini, Gemini 3.1 Pro Thinking, Claude Opus 4.5). Gemini 3.1 Pro achieves the highest overall accuracy (74.8%), followed by GPT–5–mini (69.6%) and GLM–4.5V (69.2%); roughness and depth are substantially easier than normal orientation and light direction, and several models exhibit a systematic Left/Right bias that balanced accuracy partially corrects.

We further benchmark inverse generation—scaffolded Blender Python from reference renders—on a 120–item coding subset. Verification measures headless execution yield rather than pixel match: Gemini 3.1 Pro reaches 100% after a minor API correction, Claude Opus 4.5 reaches 80.8%, while Qwen3–VL and the GPT minis lag well behind despite strong recognition scores. Together, these results separate the recognition of controlled graphics cues from reliable inverse code generation: models that rank depth or gloss well can still fail at emitting runnable scene scripts.

Technical Approach

Two-stage pipeline

Each instance flows through a headless Blender stage that constructs the scene, places two foreground objects, varies exactly one task–dependent graphics factor, and exports an RGB image together with auxiliary passes; and a Python verification stage that reads those passes under per–object masks, checks consistency with scene metadata, instantiates a question template, and writes a pixel–verified record. Items that fail the pass–metadata agreement test are discarded so that every retained label is supported by the pixels shown to a model.

Pixel verification is the load-bearing design choice. Prior synthetic benchmarks like CLEVR and Kubric derive labels from scene metadata. We derive labels from the render passes the model actually sees, which catches cases where the metadata is correct but the rendered image is ambiguous (e.g. the “closer” object is occluded). This is the core methodological departure from references and the reason we believe GRAFIQ measures graphics understanding rather than scene–graph memorisation.

Tasks and QA formulation

Four tasks span three image–formation axes; each task uses a dedicated Blender pass, has three natural–language question variants selected via seed mod |T| for phrasing robustness, and stores a forced–choice ["Left", "Right"] answer.

 depth_comparison — Geometry

Varies object placement depth. Verifier reads the depth EXR pass and computes mean camera–space depth under the per–object IndexOB mask.

 roughness_comparison — Materials

Varies surface roughness on a controlled Principled BSDF (the importer strips imported materials so the rendered glossiness corresponds exactly to the shader). Verifier reads the glossy–direct pass.

 normal_orientation — Geometry

Varies object yaw. Verifier reads the surface–normal pass and computes mean camera–facing–ness.

 light_direction — Lighting

Varies key–light direction. Verifier reads the diffuse–direct pass and computes mean per–object luminance.

Pixel-centroid “Left” / “Right”

Because every question is a forced choice between “Left” and “Right”, the benchmark is well–defined only if those two labels mean the same thing to the model and to the verifier. We anchor both to the viewer's viewpoint on the rendered image and derive the label from each object's pixel centroid (mean image–column under the IndexOB mask), independently of which scene–graph slot it occupies. The smaller–column object is “Left”.

Verification filter

Pixel agreement is necessary but not sufficient: a verifier metric can be correct while the cue it measures is invisible to a viewer. We add two task–specific drop rules so that residual difficulty reflects genuine model failure rather than ill–posed evidence:

  • light_direction: drop items with per–object brightness ratio satisfying |L_A/L_B − 1| < 0.20 (below the just–noticeable–difference floor for uniform–shaded primitives).
  • normal_orientation: drop items whose object pair contains a rotationally–symmetric primitive (sphere, UV sphere, cone, ring, cylinder, capsule, disc), since such shapes are invariant under yaw about their principal axis.

On the released split, Stage 2 verified 701 candidate items; the filter dropped 88 (56 small–gap and 32 symmetric–pair removals), and the remaining 613 were subsampled to a balanced 4×120 = 480 recognition split.

Inverse generation: scaffolded Blender Python

In addition to discrimination items, the inverse formulation gives a model a reference RGB render plus a partial script.py that already loads the two foreground GLBs, and asks it to complete camera, lighting, and environment code. Verification is purely executional—Blender~4.4.3 must exit with status zero and emit a frame—rather than pixel–aligned to the reference. The reported number is execution yield, not visual similarity.

How we depart from prior work

  • Versus BLINK and PhysBench: same perceptual–probing spirit, but each item isolates exactly one of four image–formation factors and verifies the label against the exact render pass.
  • Versus CLEVR / Kubric / 3DSRBench: we keep template–based forced–choice questions and a deterministic scripted renderer, but we substitute pixel–verified labels for scene–metadata labels.
  • Versus the proposal's own first iteration: world–coordinate Left/Right was replaced with viewer–pixel–centroid Left/Right after a silent axis bug pushed Qwen below chance (Section: Problems & Lessons).
